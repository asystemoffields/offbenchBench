# offbenchBench

This skill is a thin wrapper. The protocol is model-agnostic and lives in plain Markdown next to this file.

1. Read `AGENTS.md` in this directory. It is the full set of instructions: scope, the stakes tiers, how feasibility is measured, and the rules that don't bend.
2. Check `ledger/` for work in progress before you start anything new.
3. If the user brought a problem, make one card and go to phase 2. Otherwise follow `protocol/1-discover.md` through `protocol/5-contribute.md`, reading each when you reach that phase.

Both human gates apply. Get approval and a budget before solving, and get approval of the exact text before any public action. Scale the verification to the tier, never below it.
